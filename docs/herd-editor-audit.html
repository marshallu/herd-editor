Herd Editor audit report

A read-only review of the current Herd Editor working tree, focused on security, field integrity, content preservation, performance, and editor experience.

Overall verdict

Do not roll out for production editing yet. Missing WordPress post locking permits stale overwrites, and changed block attributes are not encoded with WordPress’s required comment-safe serializer.

Prioritized findings

The first finding is a release-blocking content-integrity gap. The remaining findings are risks and maintainability defects discovered by static review; they still require live WordPress and ACF validation.

HighContent integrity

Herd does not acquire or refresh WordPress post locks

Two people—or Herd and Gutenberg in separate sessions—can edit the same post concurrently. Because Herd submits the complete title, slug, content document, and rendered meta-box fields, the later stale submission can overwrite newer work without warning.

No use of wp_check_post_lock(), wp_set_post_lock(), Heartbeat, wp-refresh-post-lock, _edit_lock, or lock-loss handling exists in the reviewed plugin. The browser’s beforeunload warning only detects unsaved local changes; it cannot detect another user’s save. Herd should use WordPress’s shared lock, show an existing-lock/takeover screen, refresh ownership through Heartbeat, disable editing immediately on lock loss, and verify ownership or a freshness token on the server immediately before accepting a save.

Screen entryFull post formLocal-only unload guard

HighContent integrity

Changed block attributes bypass WordPress’s required comment escaping

Any edited or newly inserted block is serialized with raw JSON.stringify(). Field values containing backslashes, double hyphens, angle brackets, ampersands, or escaped quotes therefore produce block comments that differ from WordPress’s canonical and HTML-safe representation. This can cause invalid HTML comments, parser disagreement, Gutenberg block-recovery prompts, or content corruption during an editor round trip.

WordPress’s serialize_block_attributes() deliberately converts those sequences to Unicode escapes and states that its PHP output must remain synchronized with the JavaScript block editor. Herd preserves untouched comments byte-for-byte, but the first field change regenerates that block’s opening comment without those protections. Replace the custom encoding with WordPress-equivalent serialization and add adversarial round-trip fixtures containing -->, --, HTML, ampersands, backslashes, quotes, Unicode, and nested repeater values.

MediumContent integrity

Editing one ACF field can discard legacy data that the current form does not render

If a block comment still contains values for a renamed, removed, unavailable, or conditionally non-rendered field, the first change to any rendered field replaces the complete data object with ACF’s current form serialization. Keys absent from that serialization are lost on save.

This is not an invented-field problem: the visible controls come from the real ACF form. It is a preservation problem at the serialization boundary. The bridge emits { data }, and the application merges that as the block’s new, whole data attribute. Add an explicit preservation policy: merge serialized keys into existing data while deliberately deleting only keys ACF proves belong to fields removed by the user, or confirm with live ACF tests that every supported hidden/disabled field is always serialized. At minimum, detect omitted pre-existing keys and warn before save.

MediumContent integrity

Save, redirect, and starter-content behavior lacks WordPress integration coverage

A regression in the new default-editor redirect, auto-draft seeding, revision message carry-through, or post.php round trip could escape the JavaScript suite and affect authored content or editor routing.

The logic is careful and capability-gated, but it depends on WordPress request order, Classic Editor hooks, post templates, ACF field-key lookup, and redirect query arguments. Those behaviors cannot be established by syntax checks alone.

MediumRecovery

There is no autosave or crash-recovery path for Herd changes

A browser crash, expired login, network interruption, tab termination, or long-session failure can lose every change since the last manual Update. The in-memory undo history disappears with the page.

The editor tracks dirty state and keeps up to 50 in-memory history states, but it does not send WordPress autosaves, create per-user autosave revisions, recover a newer autosave, refresh long-lived nonces, or provide a local recovery draft. At minimum, implement WordPress-compatible autosave/recovery and test ACF block data plus native meta boxes. Autosave must respect the same post lock so it cannot become another stale writer.

Memory-only historyDirty-state handlingEnqueued editor assets

MediumValidation

Collapsed ACF blocks are absent from form-level validation

Herd only fetches and mounts an ACF form while its panel is open. ACF’s classic form validator scans the fields currently inside form#post; unopened or collapsed blocks have no field nodes to validate. A post can therefore be submitted while required or custom-validated fields in those blocks are invalid.

Gutenberg’s ACF integration separately walks its registered block instances during save. Herd does not reproduce that whole-document validation and explicitly requests no validation response when fetching a block form. Before publish, validate every ACF block’s serialized data against its actual field group on the server, return block-addressable errors, open the affected panel, and focus the first invalid field. Draft policy should be decided explicitly rather than inherited accidentally.

MediumWordPress policy

The inserter and structural controls bypass block eligibility and locking policy

Herd catalogs every registered ACF block and checks only registration plus supports.multiple. It does not apply allowed_block_types_all, inserter support, parent/ancestor constraints, post/editor context, template locks, or per-block lock attributes. Editors can be offered blocks or structural operations that Gutenberg intentionally forbids.

This is active on the reviewed site: the theme has an explicit allowed-block list and comments out acf/slate-form, while Herd’s grouping includes it and its registry-driven catalog can offer it when registered. New-post template serialization also explicitly removes the lock attribute, and existing locked ACF blocks are still given duplicate/delete/reorder controls. Build the catalog from WordPress block-editor settings for the current post and enforce every rule in mutation code as well as in the UI.

All registered blocks catalogedEligibility checkTemplate lock removedSite allowed-block policy

MediumACF compatibility

ACF’s post-meta block storage mode is neither supported nor rejected

ACF blocks configured with usePostMeta load and save values through post meta rather than ordinary block-comment data. Herd assumes every ACF block’s authoritative values live in the comment and would serialize edits there without implementing the corresponding post-meta update path.

No reviewed HerdPress block currently declares this mode, so this is a compatibility trap rather than active loss on the present block set. Publish the storage mode in block metadata and make those blocks read-only until Herd implements and integration-tests ACF’s native persistence path. The same defensive rule should apply to future ACF storage features Herd does not recognize.

Comment-data request modelComment-data update modelACF post-meta mode

MediumPlugin removal

“Plugin disappears safely” depends on an orderly, uninterrupted deactivation

The Spacer fallback is not intrinsically inert without Herd. Database-backed spacers are rewritten to Message fields only when WordPress runs the deactivation hook; direct file removal, a failed deployment, or an interrupted bulk conversion can leave unknown field types. Local JSON/PHP field groups cannot be converted at all and can be changed to Text fields if re-saved without Herd.

The code documents much of this limitation, but it weakens the architectural guarantee. The conversion also updates fields one at a time without checking results, recording progress, or providing a transaction/rollback report. Prefer an ACF-native layout type if one can represent the spacer, or ship a separate always-available compatibility shim for the field type. At minimum, add preflight inventory, idempotent logged migration state, result checking, WP-CLI verification, and an operational removal procedure that is tested in deployment—not only through the Plugins screen.

Deactivation conversionUnchecked per-field updatesDocumented local-group limitation

MediumField integrity

DOM-preserving ACF adaptations remain coupled to upstream markup

An ACF markup or event-hook change could leave controls visually present but disconnected, particularly in table repeaters, flexible layouts, cloned rows, media fields, and nested groups.

The implementation deliberately moves existing inputs and preserves ACF data attributes rather than recreating controls. The 254-test suite exercises these contracts well, but fixtures model expected ACF output and are not a substitute for smoke tests against the installed ACF Pro version.

MediumPerformance

The editor payload and observer-heavy UI need measurement on long pages

Pages with many blocks, repeaters, or flexible layouts may show slower mount, typing, cloning, or expand-all behavior even though functional tests pass.

The built assets total 597,546 bytes uncompressed and approximately 122,841 bytes gzip-compressed. The UI also installs scoped mutation observers and multiple input/change listeners. Their implementations avoid full-form rescans in key paths, but no timing, memory, or large-document benchmark was present.

LowSecurity

The theme icon set reaches innerHTML without the block-icon allowlist

Markup returned by mu_icons() or altered through herd_editor_icons is published without sanitization and inserted with innerHTML. A compromised or unexpectedly data-driven icon provider could execute admin-side markup.

Registered block icons follow a narrow server-side SVG allowlist, but the named icon-picker set does not. Apply the same allowlist to every icon in herd_editor_icon_set(), discard empty results, and add hostile fixtures for scripts, event handlers, external references, foreign objects, and malformed SVG. The present source appears theme-authored, so this is defense in depth rather than evidence of an exploitable untrusted input today.

LowUX / maintainability

Repeater add-button normalization can damage intentional capitalization

Labels containing acronyms or proper names are rewritten with toLowerCase(), so “Add FAQ” becomes “Add faq” and a field-group author’s intended wording is lost.

Preserve the authored label and only normalize the first character when it is lowercase, or make sentence-case transformation an explicit profile choice.

Passed checks

These controls were confirmed by code inspection or automated execution. A pass means the reviewed implementation contains the control; it does not expand the audit beyond the limitations below.

Authorization is post-specific

Access requires both manage_options and edit_post by default, with unsupported post types rejected at render time.

Form submissions retain core authorization protection

The editor posts to WordPress post.php with the standard update-post nonce and original fields. That protects authorization and CSRF; it does not prevent stale concurrent writes.

Profile settings validate intent

User-level editor preferences verify a dedicated nonce, capability, and a strict three-value allowlist.

Most output paths are escaped

Titles, URLs, labels, attributes, notices, and registered block SVGs use context-appropriate escaping or explicit allowlists. The separate theme icon-set exception is documented above.

Field nodes are preserved

DOM decorators move existing ACF controls and retain the selectors and data attributes used by upstream event delegation and serialization.

Untouched document regions are byte-conscious

Tests cover nested round trips, immutable movement, history, and preservation of malformed or freeform content. Regenerated attribute comments have the core-escaping defect documented above.

Progressive failure is considered

Controls that require JavaScript ship hidden or fall back to native ACF behavior, limiting dead affordances when the bundle fails.

No remote runtime dependency

The plugin assets and this report are local; the report contains embedded CSS only and no scripts, iframes, forms, or remote resources.

Recommendations

Post locking and stale-save prevention are required before rollout. Autosave/recovery and the remaining work materially improve content safety and maintainability.

  1. Implement native post locking and server-side stale-save rejection.

    Use WordPress’s shared lock across Herd, Gutenberg, and Classic; add Heartbeat refresh, lock-owner and takeover UI, immediate lock-loss handling, and a final server-side ownership/freshness check before saving.

  2. Adopt WordPress’s block-attribute serializer exactly.

    Match the core JavaScript/PHP escaping contract and test hostile comment sequences before allowing edited block data to reach post_content.

  3. Validate the complete ACF block document before publish.

    Validate serialized data for mounted and unmounted blocks on the server, map errors back to block rows, and prevent the final write when any applicable field rule fails.

  4. Honor WordPress block eligibility and locks.

    Build the inserter from current editor settings and enforce allowed types, context, inserter support, parent/ancestor constraints, multiplicity, template locking, and per-block movement/removal locks in the mutation layer.

  5. Reject unsupported ACF persistence modes.

    Identify usePostMeta and future unrecognized storage modes in server metadata and keep affected blocks read-only until their native save behavior is implemented and tested.

  6. Make Spacer removal operationally verifiable.

    Add inventory, checked/idempotent conversion reporting, WP-CLI verification, and a tested deployment-removal runbook; consider a compatibility shim that survives removal of the editor UI.

  7. Add autosave and recovery.

    Persist recoverable per-user drafts for the complete Herd document and supported meta, surface newer autosaves on reopen, refresh required nonces, and ensure autosave respects the active lock.

  8. Add a WordPress integration matrix.

    Exercise two-user and two-editor races first, followed by existing posts, new auto-drafts, publish/update/schedule/revision/autosave/preview flows, direct native-editor links, site defaults, per-user overrides, and Classic Editor installed or absent.

  9. Define and test legacy ACF-key preservation.

    Seed blocks with active fields plus removed, renamed, conditionally hidden, disabled, and unknown keys. Change one visible value, save, reload, and assert exactly which keys may disappear. Warn or preserve when the form omits pre-existing data unexpectedly.

  10. Run live ACF smoke tests against supported versions.

    Create, duplicate, reorder, collapse, edit, and delete nested repeater and flexible-content rows; save, reload, and compare stored block markup and field values.

  11. Benchmark representative long documents.

    Record mount time, expand-all time, keystroke responsiveness, mutation counts, and memory on realistic high-row pages; set a regression budget.

  12. Sanitize both SVG sources and harden the test corpus.

    Pass the theme icon map through the existing server allowlist, then prove that scripts, event attributes, external URLs, foreign objects, and malformed SVG cannot survive either rendering path.

  13. Preserve authored button labels.

    Avoid lowercasing the full repeater add label; retain acronyms and proper names supplied by the field-group author.

Audit limitations

This audit was read-only. No plugin source, theme source, field-group JSON, build artifact, database row, setting, or user preference was modified during the audit.

No authenticated browser session

The WordPress admin editor was not exercised with a real user, live ACF forms, third-party meta boxes, or media-library interactions.

No persistence comparison

No production-like database snapshot was saved and reloaded, so source-level preservation claims rely on unit fixtures and implementation review.

No load or compatibility lab

No multi-browser, assistive-technology, plugin-conflict, PHP-version, WordPress-version, ACF-version, or large-document performance matrix was run.
